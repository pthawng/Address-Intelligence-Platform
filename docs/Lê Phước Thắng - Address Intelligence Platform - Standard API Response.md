# Standard API Response

All JSON endpoints use the shared helpers in internal/platform/httpserver.
JSON keys use snake_case, including DTO fields (explicit json tags required).
Messages are human-readable, optional for success, fixed English defaults for
mapped errors; clients branch on HTTP status and error.code, not message text.
Endpoint success messages may be localized by the caller.

## Success

```json
{"success":true,"status":200,"message":"Retrieved successfully","data":{"id":1,"name":"Example"}}
```

```go
return httpserver.Success(w, r, http.StatusOK, "Retrieved successfully", result)
// Without a message:
return httpserver.JSON(w, r, http.StatusOK, result)
```

The helper owns success/status; status always matches the actual HTTP status.
Data is always present, including null for nil. Pass the DTO as data, not another
envelope. JSON/Success reject non-2xx and bodyless status codes before commitment.
Serialization failures are returned to Adapt and mapped to a generic 500.

For list endpoints use Paginated; nil items become [], never null:

```json
{"success":true,"status":200,"data":[],"meta":{"page":1,"limit":10,"total_records":0,"total_pages":0}}
```

```go
return httpserver.Paginated(w, r, items, page, limit, totalRecords)
```

Pages are one-based, limit is positive and total_records is nonnegative int64.
Total_pages is computed with overflow-safe ceiling division. Zero records means
zero pages; pages beyond the last return an empty list. Contradictory metadata
returns an internal error before writing. Validate user pagination input in the
transport (including a route-specific maximum limit); return INVALID_INPUT for
bad input before calling the application. The helper validates the result contract,
not raw query parameters. Totals count records matching the same filters.

## Errors

```json
{"success":false,"status":400,"error":{"code":"INVALID_INPUT","message":"Invalid input","details":[{"field":"email","message":"Invalid email format"}],"request_id":"server-generated-id"}}
```

All mapped errors, including routing, JSON decoder and recovered panic errors,
share this envelope. Details are omitted unless explicit safe field violations
exist. Request_id remains inside error for compatibility with Error Foundation;
it matches X-Request-ID and is omitted outside request correlation middleware.

```go
return &apperror.ValidationError{Details: []apperror.FieldViolation{
    {Field: "email", Message: "Invalid email format"},
}}
```

Use API field paths (e.g. address.postal_code) and public messages only. Never
include rejected values, raw validator errors, SQL/driver errors or credentials.
Only the outermost ValidationError can expose details. An INTERNAL_ERROR wrapping
validation, or another error classification, cannot expose nested details.
Raw err.Error() is never sent to clients. Wrap errors using %w; errors.Is/As work.

## HTTP semantics

| Status | Usage |
| --- | --- |
| 200 | Successful GET/PUT/PATCH, or POST operations that do not create a resource |
| 201 | Resource created; set Location when the resource has a retrievable URI |
| 204 | Successful operation with no response body; typically DELETE |
| 400 | Invalid input, missing fields or malformed JSON |
| 401 | Missing/invalid authentication (UNAUTHORIZED) |
| 403 | Authenticated caller lacks permission (FORBIDDEN) |
| 404 | Resource or route not found |
| 405 | Method not allowed; router sets Allow |
| 413 / 415 | Oversized JSON body / unsupported media type |
| 429 | Rate limit exceeded |
| 500 | Internal/unclassified error |
| 503 | Provider unavailable |

```go
w.Header().Set("Location", "/places/" + result.ID)
return httpserver.JSON(w, r, http.StatusCreated, result)
// Delete with no representation:
return httpserver.NoContent(w, r)
```

204 deliberately has no envelope, Content-Type or body. An empty list normally
uses 200 with data:[] rather than 204. HEAD has no body but preserves status and
representation headers. Authentication middleware must set the appropriate
WWW-Authenticate challenge before returning ErrUnauthorized; no authentication
scheme is invented by the mapper. This foundation adds error identities/mapping,
not an authentication/authorization implementation.

Protocol parsing failures generated by net/http before dispatch and canonical
redirects retain their native HTTP behavior. Streaming/download handlers, when
introduced, must declare their own non-JSON contract explicitly.

## Timestamps

Use time.Time in response DTOs and normalize with httpserver.Timestamp(value).
The Go JSON encoder emits RFC 3339 (ISO 8601), UTC with Z, retaining available
fractional seconds. Example: 2026-09-22T21:58:00Z. Never use local display formats
or Unix numbers for API timestamps. Use *time.Time for nullable timestamps and
normalize the pointed-to value when present. The helper does not traverse arbitrary
DTOs or reinterpret user-provided strings; timestamp normalization belongs in the
transport DTO mapping.

## Migration and checks

JSON now wraps its value instead of returning it directly. Health responses are
now {"success":true,"status":200,"data":{"status":"ok"}}; HTTP probe behavior
is unchanged. Errors gain success:false and status while preserving the existing
error payload. Consumers of previous bodies must update their field access.

Tests cover success/error shapes, HTTP/body status agreement, 201/204/HEAD,
empty and out-of-range pages, int64 overflow, field detail exposure, 401/403,
UTC serialization and the actual health endpoint response.
